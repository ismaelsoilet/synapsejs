# SynapseJS 1.9.0 — Production-readiness audit fixes (security hardening)

**1.9.0 não traz feature nova: ela tira do framework os defaults inseguros e as afirmações que a
própria evidência não sustentava.** Quatro comportamentos que quebravam passam a ser recusados por
padrão, a camada de hardening que faltava entra em vigor, e cada número que o projeto publica sobre si
mesmo passa a ser derivado de uma fonte que um teste consegue conferir.

Quem está na 1.8 tem um guia passo a passo: **[`docs/migration-1.9.md`](../migration-1.9.md)** (EN) ou
**[`docs/migracao-1.9.pt-BR.md`](../migracao-1.9.pt-BR.md)**. O contrato da fatia não mudou — mesmo
arquivo, mesmos exports, mesmas actions `Result<T, E>`.

---

## Segurança: o que estava aberto e agora não está

| Classe de defeito | Severidade | Teste que falha se voltar |
|---|---|---|
| Travessia de caminho no scaffolder e no upload (uma fatia plantada em app vizinho era importada, migrada e exposta como RPC) | crítica | `scaffolder.test.ts`, `cli-contract.test.ts` |
| SSE sem autorização (qualquer nome de tópico), origem de WebSocket fail-open, sem limite de conexões | crítica | `sse-gateway.test.ts`, `http-response-hardening.test.ts` |
| Nenhum header de segurança em resposta alguma; CDN de terceiros ligado por padrão; erro interno exposto no RPC | alta | `http-response-hardening.test.ts` |
| Identidade por header sem opt-in; tenant vindo de header falsificável | alta | `session-security.test.ts` |
| Revogação existia mas nunca era consultada na requisição | alta | `session-security.test.ts` |
| Upload multipart sem teto de bytes; idioma de `content-length` que aceitava tamanho desconhecido | alta | `uploads.test.ts`, `abuse-resistance.test.ts` |
| Registro de rate limit ilimitado que apagava contadores vivos; identidade spoofável | média | `production-hardening.test.ts` |
| Pre-check de SSRF descartava o IP validado (segunda resolução podia alcançar host privado) | média | `abuse-resistance.test.ts` |
| `delete` do S3 sem assinatura; otimizador de imagem sem autenticação | média | `storage.test.ts`, `http-response-hardening.test.ts` |
| `/health` publicava tabela de rotas, caminhos e texto de erro para anônimos | média | `runtime-server.test.ts` |
| Shutdown fechava o banco num timer de 200 ms e descartava a promise de drenagem | média | `graceful-shutdown.test.ts` |
| Regex com retrocesso quadrático no gate de vazamento e no gerador de DDL | baixa | `abuse-resistance.test.ts` |

Também entrou: teto de corpo no nível do processo (12 MiB) atrás dos limites por rota, upload que
confere os bytes contra a extensão declarada, rate limit em toda superfície que aceita requisição
(inclusive páginas renderizadas), confiança em proxy opt-in, revogação consultada por requisição com
memo limitado e tabela podável, e `synapse impact` que falha em alvo inexistente em vez de devolver
sucesso vazio.

## As quatro mudanças que quebram (todas com migração)

1. **Cookie seguro por padrão** — `ctx.setCookie(name, value)` agora emite `HttpOnly`, `Secure` e
   `SameSite=Lax`; `false` explícito desliga.
2. **SSE exige tópico declarado e sessão autenticada** — `defineTopic({ name, owner, readRoles? })`,
   tópicos separados por tenant, `ctx.broadcast` só notifica quem é `owner`.
3. **Upgrade de WebSocket fail-closed na origem** — `SYNAPSE_ALLOWED_ORIGINS` obrigatório em produção,
   com carve-out de loopback; origem ausente ou `null` sempre recusada.
4. **CDN de terceiros opt-in e CSP estrita por padrão** — `SYNAPSE_ENABLE_CDN` + hashes de integridade;
   seu CSS em `public/synapse.css` sempre ganha.

Além dessas, em produção sem `SYNAPSE_SESSION_SECRET` o `synapse start` **recusa subir** (a menos de
`--acknowledge-insecure`), e identidade por header exige `SYNAPSE_DEV_HEADERS=true` fora de
`development`/`test`.

## Honestidade das afirmações, agora executável

- Uma fonte única (`packages/synapse/src/project-status.ts`) define versão, inventário de features,
  adoção e contagem de ferramentas; `synapse info`, `/health` e o MCP leem dela. **Nenhum literal de
  versão sobrevive fora do manifest.**
- `bun run docs:check` roda a suíte, conta testes/arquivos, roda o linter com o limite de exibição
  levantado, e falha se qualquer número publicado divergir — inclusive a tabela de features
  (46 `stable`, 3 `experimental`, 1 `roadmap`) e a contagem de ferramentas (18, derivada da lista
  registrada, não digitada).
- Afirmações falsas foram **apagadas**, não amaciadas: compatibilidade com Drizzle/Kysely (não existe
  adapter), "workflow de release nunca rodou", "nada publicado no npm", nome de ferramenta MCP que não
  existe, e números de benchmark que o script citado não reproduzia.
- Ratings caíram onde a evidência era um template ou um dublê; subiram onde passou a existir prova real
  (jobs, WebSockets, cache SSR, webhook com assinatura, `sliceMeta`, rollback, hidratação).

## Upgrade em três linhas

```bash
bun add @ismaelsoilet/synapsejs@1.9.0
SYNAPSE_SESSION_SECRET="$(openssl rand -base64 48)" bun run start   # produção
SYNAPSE_DEV_HEADERS=true bun run dev                                # desenvolvimento
```

Se você usa SSE, WebSocket ou o CDN, veja o guia de migração — cada mudança traz o sintoma, o motivo e
a flag que restaura o comportamento antigo onde restaurar é seguro.

## O que continua em aberto (dito aqui, não escondido)

- **Zero adotantes externos** — nenhum deploy de terceiros é conhecido; `stable` significa "há teste
  que falha se regredir".
- Rate limit, cache de SSR e event hub são **por processo** (N instâncias = N vezes a cota).
- A publicação usa token de npm de longa duração; trusted publishing sem token não está configurado.
- A imagem de container exige segredo de sessão em produção — recusa subir sem, de propósito.
- O `typescript` permanece na imagem: o framework typechecka fatias em runtime.

<summary>English summary</summary>

1.9.0 is a security-hardening release with four breaking behaviour changes — secure-by-default cookies,
declared SSE topics with authenticated subscribers, fail-closed WebSocket origin, and an opt-in
third-party CDN under a strict CSP. Production startup without `SYNAPSE_SESSION_SECRET` is now refused
unless explicitly acknowledged, and caller identity headers require `SYNAPSE_DEV_HEADERS=true` outside
development. A single machine-readable source now drives the version, feature inventory and tool count,
and `bun run docs:check` fails when any published number drifts. False claims (Drizzle/Kysely
compatibility, never-published status, unreproducible benchmarks) were deleted rather than softened.
Upgrade guide: [`docs/migration-1.9.md`](../migration-1.9.md).

</details>
